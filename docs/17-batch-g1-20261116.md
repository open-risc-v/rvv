## 2. 本轮修掉的两个骨架 bug

这两个都是模板层面的问题，会打在所有后续新工程上，所以改的是
`rvv-port-project/assets/skeleton/`，不只是某个工程。

### 2.1 `scripts/build.sh` 是宿主直编，macOS 上必然失败

`build.sh` 直接 `cmake --preset`，在 macOS 上 CMake 找不到
`CMAKE_MAKE_PROGRAM`、`CMAKE_C_COMPILER`，五个包全部 configure 失败。

**这不说明脚本写错了**——它本来就是给"Linux 宿主"用的。问题在于没有一条
"macOS 上怎么办"的明确路径。解决办法是主仓新增 `scripts/container-check.sh`：

```bash
./scripts/container-check.sh ../speexdsp-rvv          # 默认 rvv-cross:2
IMAGE=rvv-cross:3 ./scripts/container-check.sh ../nettle-rvv
```

它做四件事：交叉 configure + build、跑 `cpu_probe`、跑 `diff_kernels`、跑 `run_ab.sh`。

### 2.2 `run_ab.sh` 把用例脚本本身交给 qemu 执行

原写法：`STAGE=gen ... run bash "${c}"`，其中 `run() { ${RUNNER} "$@"; }`。
于是变成 `qemu-riscv64 -L /usr/riscv64-linux-gnu bash 00_framework.sh`，
而 sysroot 下根本没有 riscv 版 bash → 用例在 gen 阶段直接挂，
报的却是"生成输入失败，可能是上游未就位"，**指向完全错误的方向**。

修法分两半：

- `run_ab.sh`：三处改成 `RUNNER="${RUNNER}" bash "${c}"`，脚本用宿主 bash 跑；
- 用例：`${RUNNER:-} "$BIN/diff_kernels"`，由用例自己包裹被测二进制。

后者也让用例在**板子上**能跑：真机上不设 `RUNNER`，`${RUNNER:-}` 展开为空，直接执行本地二进制。

## 3. mpg123 的特殊路径：没有公开 git 仓库

mpg123 官方只有 sourceforge 的 svn 和 release tarball。实测五个候选 URL 全部
`not found`：

```
https://git.code.sf.net/p/mpg123/mpg123         → not found
https://git.code.sf.net/p/mpg123/code           → not found
https://git.code.sf.net/p/mpg123/mpg123-src     → not found
https://codeberg.org/mpg123/mpg123              → not found
https://github.com/mpg123/mpg123                → not found
```

`svn` 在 macOS 上不预装，所以走官方 tarball：

```
https://mpg123.org/download/mpg123-1.33.7.tar.bz2
sha256 = 31d0e35a4ca567ec9b5ebda6c3062bb4435d6d3eacd6ef0d95cadd7854dc03ee
```

**`fetch-upstream.sh` 对它不适用**（脚本按 git clone 设计，空 URL 会拒绝执行）。
`baseline/` 是手工 curl + 解包得到的，`project.conf` 里 `UPSTREAM_URL` 记 tarball 地址、
`UPSTREAM_SHA` 记 sha256 而不是 commit。别的包不要学这条路径——只有确认没有公开 git
仓时才用，并且必须留下 sha256。

## 4. `data/status.csv` 的 CSV 引号坑

写 libvpx 那行 evidence 时用了 `{a,b,c}.md` 这种花括号写法，**没加引号**，
逗号把这一行撑成 12 个字段。后果是 `csv.DictReader` 回读时多出一个 `None` 键，
再写回直接抛 `ValueError`，而**文件在抛错前已经被 `open(...,'w')` 截断成 9 行**。

恢复与预防：

- 已经 `git checkout -- data/status.csv` 还原（最新提交里的版本是完整的）；
- 写回时用 `csv.reader` / `csv.writer` 走正规转义，不要让字符串拼接碰 CSV；
- 改完必须跑 `./scripts/verify.sh`，它会拦字段数不齐。

## 5. 下一轮

五个包都卡在同一个位置：`cmake/upstream.cmake` 还是空的，`run_ab.sh` 通过的是
**骨架自检用例**，不是真实包路径。下一轮要按包分别接上游：

- speexdsp / flac / mpg123 / nettle：autotools / CMake，各有自己的 `configure`
- stockfish：单文件 `make`，`ARCH=riscv64` 已有分支，可先确认它能编

接完之后再谈 RVV 内核。这五个包里 SIMD 面各不相同：speexdsp 是重采样与 FFT、
flac 是 LPC 与立体声去相关、mpg123 是 IMDCT 与合成滤波器、nettle 是分组密码与哈希、
stockfish 是 NNUE 增量更新。都不是"一个内核打天下"的形态，要按各自热点挑。
