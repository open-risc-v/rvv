# 迁移到新设备的完整清单

**日期**：2026-11-16
**用途**：把整套 RISC-V RVV 移植工程搬到另一台机器继续做，不必重新摸索环境。

## 0. 一句话

主仓 clone 下来 → 28 个子模块 init → 装 skill → 起容器镜像 → 跑 `./scripts/verify.sh`，
四步之后状态与源设备完全一致。真机（如果有）单独配。

## 1. 拉取仓库

```bash
git clone https://github.com/open-risc-v/rvv.git
cd rvv
git submodule update --init --recursive     # 28 个子模块
```

28 个子模块全部是 public 仓库，不需要凭据。若某个仓库打不开，先查
`git submodule status` 里那个指针的 sha 是否在远端存在（历史上做过一次全量
`filter-branch` 改写，旧 sha 会失效，届时 `--remote` 拉最新即可）。

## 2. 装 skill

skill 的源码随主仓版本化在 `skill/rvv-port-project/`。新设备上：

```bash
cp -R skill/rvv-port-project <该设备的 workspace>/.user_skills/
```

`<该设备的 workspace>/.user_skills` 就是其他已装 skill 所在的同级目录
（本机是 `~/.doubaowork/agent_mode/workspace/.user_skills`）。装完确认：

```bash
python3 <skill-creator 的 scripts>/quick_validate.py \
  <workspace>/.user_skills/rvv-port-project
```

skill 里三样东西是这套流程的核心资产：`assets/skeleton/`（工程模板）、
`scripts/new_project.py`（一条命令生成骨架）、`references/`（构建系统适配与门禁口径）。

## 3. 容器镜像

所有交叉编译都在容器里做，**宿主（尤其 macOS）不编任何东西**。

| 镜像 | 内容 | 用途 |
|---|---|---|
| `rvv-cross:1` | Ubuntu 24.04 + `riscv64-linux-gnu-gcc 13.3` + qemu + cmake/ninja/meson/autotools | 通用交叉 |
| `rvv-cross:2` / `:3` | 同上，多带 `gcc-14`（**但 g++ 只有 13**） | 需要 GCC14C 时 |

镜像不在主仓里，重建方法：任取一个工程的 `scripts/Dockerfile.buildenv` 作起点，
补上 `gcc-riscv64-linux-gnu`、`g++-riscv64-linux-gnu`、`qemu-user`、`cmake`、`ninja-build`、
`meson`、`autoconf`/`automake`/`libtool`。验证：

```bash
docker run --rm rvv-cross:2 bash -lc 'riscv64-linux-gnu-gcc --version | head -1; qemu-riscv64 --version | head -1'
```

## 4. 跑一遍自检

```bash
./scripts/verify.sh          # 数据一致性（status.csv / plan.csv / deps.csv）
python3 scripts/dashboard.py # 重新生成 STATUS.md
```

`verify` 必须是 PASS。它会校验 `status.csv` 的列数与字段合法性——这一步很重要，
因为 CSV 字段里出现未转义的逗号会把行撑成 12 列，而且 `open(...,'w')` 会在报错
**之前**就把文件截断。任何手改 CSV 都用 `csv.writer`。

## 5. 真机（可选）

真机是 SpacemiT K3 级别的板子（8 核 16 GB，`rv64imafdcvh` + RVV 1.0 + 全套 `Zvk*`，
VLEN=256）。连接信息不进仓库，用环境变量带：

```bash
export BOARD_HOST=<板子地址>
export BOARD_PASS=<口令>
export SSH_ASKPASS=/tmp/askpass.sh SSH_ASKPASS_REQUIRE=force DISPLAY=:0
printf '#!/bin/sh\necho %s\n' "$BOARD_PASS" > /tmp/askpass.sh && chmod +x /tmp/askpass.sh
ssh -n -o PreferredAuthentications=password -o PubkeyAuthentication=no \
    -o NumberOfPasswordPrompts=1 root@"$BOARD_HOST" 'gcc --version | head -1'
```

板侧已有的产物布局（`/root/rvv-k/*`、`/root/sf/*`）在源设备上，新板子上要重新放；
每个包的 A/B 脚本都在该工程 `scripts/` 下，照着它重跑即可。

## 6. 环境差异必须先知道

这套流程踩过的环境性坑，换机器会再遇到：

| 现象 | 原因 |
|---|---|
| `timeout` / `setsid` / `sshpass` / `bc` / `svn` 找不到 | macOS 自带工具集里没有；脚本里不要依赖 |
| 容器里编不过 `-DUSE_RVV`、编不过 Eigen RVV10 | GCC 13 的 `riscv_vector.h` 只给 masked 形式，新 intrinsic 面要 GCC 14/15；`rvv-cross:2/3` 只有 g++-13 |
| qemu 下哈希对、真机不对（或反之） | qemu 对 RVV10 多寄存器整数 kernel 模拟有缺陷，**功能都不可信**，更不能当性能 |
| 容器内前台调 docker 偶发挂载不可见 | 用后台任务跑 |
| Bash 命令 stdout 只剩尾部 | 统计类输出写文件再读 |

## 7. 大文件与生成物策略

仓库里刻意不入库的东西（换机器时不要当成丢失）：

| 文件 | 原因 | 重建方式 |
|---|---|---|
| `*/src/src/*.nnue`（stockfish，138 MB） | 体积 | 上游 `scripts/net.sh` 自动下载；文件名即 sha256 前 12 位 |
| `src/mlkem-tables.h`、`src/sntrup*`（nettle） | autotools 从 `.data` 生成 | `autoreconf -fi && ./configure && make` |
| `big.png`（libpng） | 测试语料 | `mkpng.c` 重新生成 |
| `build/` 全部 | 交叉构建产物，可达数 GB | 各包 `scripts/*-ab.sh` 或 `scripts/container-check.sh` |

**特别注意**：`nettle-lfib-stream` 不带出口，裸重定向会一直写（本轮写满过 17 GB 磁盘，
并连带把 OrbStack 的 docker daemon 打死）。任何用它做语料的地方都要 `| head -c N`。

## 8. 当前状态快照（迁移前）

48 个核心项：**G3 17 / G2 4 / G1 6 / G0 21**。

- G3（17）：libjpeg-turbo、pixman、libpng、zlib-ng、openssl、libgcrypt、libwebp、libvpx、
  openh264、libaom、x264、zimg、libde265、opus、eigen、crypto++、stockfish
- G2（4）：webrtc-audio-processing、botan、fftw、gromacs
- G1（6）：ceph、gdal、speexdsp、flac、mpg123、nettle
- G0（21）：opencv、ffmpeg、x265、openal、pulseaudio、speex、mbedtls、rocksdb、hyperscan、
  tensorflow、embree、pcl、dlib、chromium、nodejs、kodi、rust、go、vlc、libsdl2、johntheripper

口径：**广度优先**——每个包到"能编、能交叉、A/B 过、有一个 RVV 加速路径"即算达标，
深度调优留到下一轮。排除 gdal 与 ceph 的 G3 推进（仍是子模块，保留代码）。
