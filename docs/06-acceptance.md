# 06 验收口径与证据要求

验收分四类。**分类在 G0 就定死**，不允许中途改口径（改口径等于改验收标准，必须重走 G0 评审）。

## 1. bit-exact（最严格）

适用：编解码（H.264/VP9/AV1/HEVC/JPEG/PNG/FLAC/Opus 解码）、定点音频（speex/speexdsp）、
密码学（openssl/nettle/libgcrypt）、棋类评估（stockfish/gnubg）、有格式契约的文件处理。

**通过标准**（全部满足）：

1. `test/ab_run.sh` ALL PASS：A（`src/`，开 RVV）与 B（`baseline/`，同样编译选项）产出的
   二进制产物**逐字节一致**；
2. 交叉解码一致（编码器 A 出的流由 B 解码、B 出的流由 A 解码，PCM/像素完全一致）；
3. 上游自带回归集通过（ffmpeg `fate`、libvpx `test/`、x264 `checkasm`、openssl `test/`）；
4. 内核级差分测试进 CTest，覆盖：随机输入、极值、长度边界（含非 VL 整数倍）、
   尾部毒化（`vlen={128,256,512}` × `{ta,ma}` 四策略）；
5. 差分测试的**比较次数**写进 `docs/final-report.md`（例：414,537 组 0 失配）。

**常见的不合格**：只跑了 e2e 没跑内核差分（e2e 覆盖率低，抓不到单内核错误）；
只在 qemu 跑（qemu 不暴露未初始化/UB 的死循环）；把 `-march` 不同的 A/B 当对照。

## 2. 一致（consistency）

适用：编码器（x264/x265/vo-aacenc）、有损但要求"同输入同输出"的工具
（zimg 缩放、SDL blit、libimagequant）。

**通过标准**：

1. 同一输入在 A/B 两侧产出**完全一致**（不是"看起来一样"）；
2. 如果允许容差（编码器），必须给出**质量指标对照**：BD-rate / PSNR / SSIM 漂移 ≤1%，
   且码率变化在 ±3% 内（否则说明 RD 决策被改变）；
3. 固定随机种子，数据集版本写入 `docs/plan.md`。

## 3. 容差（numerical）

适用：浮点密集（fftw、eigen、gromacs、embree、gdal、tensorflow）。

**通过标准**：

1. 参考实现 = 同包同版本的**标量 C**（不是不同编译器的高优化版），避免把编译器差异算进残差；
2. 误差口径：相对误差 `|a-b|/max(|b|,eps)` 的 P99 与 max 都要给；
   浮点 FFT 允许 `1e-6` 量级，GEMM 允许 `1e-5` 量级（按数据类型与规模分别定，写进 plan.md）；
3. 迭代/收敛类算法（gromacs），必须证明"轨迹统计量在容差内"，不能只看首帧；
4. 不得用"性能提升"掩盖精度退化：精度不达标一律 G3 不通过。

## 4. 集成 + 缺口（integration）

适用：上游已有 RVV 的包（路径 A）与平台类（chromium/node）。

**通过标准**：

1. 缺口清单（上游已有 vs x86/NEON 侧的差集）写进 `docs/plan.md`，逐项标注"已补/不补（附理由）"；
2. 运行期分派在**无 RVV 的目标**上安全回退（用 `qemu -cpu rv64` 无 v 扩展验证，不得 SIGILL）；
3. 上游测试集通过率不低于改动前（记录基线通过率）；
4. 平台类额外要求：启动时间、首屏渲染、视频播放三条基线不劣化（±3% 内）。

## 5. 性能门（所有类型都要过）

- **分母**：同编译选项、`RVV_KERNELS=OFF` 的构建（即只靠 `-march` 自动向量化），
  **不是**标量 C，也不是不同 `-O` 级别。
- **测量**：真机、同会话、A/B 交替 ≥5 对，取中位数；记录负载/温度/桌面会话状态。
- **门槛**（按类型，写进项目 `plan.md`）：
  - 媒体/图像端到端：≥15% 时间下降，或 ≥2× 内核加速；
  - 音频/实时：≥10%，且时延 P99 不退化；
  - 数学/科学：达到同频 AVX2 实现的 70%（或上游 SSE 版的 60%）；
  - 密码/压缩：≥20%（这类内核通常是纯计算，收益最容易量化）。
- **qemu 数据只做方向参考**，不得作为验收依据。

## 6. 证据清单（每个门禁必须落到文件）

| 门禁 | 证据文件 | 内容 |
|---|---|---|
| G1 | `docs/progress.md` 首条 | 骨架、构建、A/B 工具可用 |
| G2 | `docs/perf-log.md` 基线表 | 目标机/目标配置、未优化基线数字 |
| G3 | `test/` 差分测试 + `perf-log` 逐轮 | 每内核：实现说明、bit-exact 结论、收益 |
| G4 | `docs/perf-log.md` 收敛段 + 剖析表 | 覆盖度 f、剩余热点占比、停止理由 |
| G5 | `docs/final-report.md` + PR 链接 | 补丁集、上游状态、维护责任人 |

**没有证据 = 状态不算推进**。看板（`STATUS.md`）只读 `data/status.csv`，
后者由项目负责人每周更新，评审抽查证据文件是否存在。
